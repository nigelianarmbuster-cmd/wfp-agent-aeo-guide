Set Up Your Own AEO Dashboard

Build a personal dashboard that tracks how answer engines describe you, and re-run it every month.

Download the dashboard Open the sample dashboard

What you will build

A personal AEO dashboard. It is a single web page you open in your browser. It shows how often the major answer engines — ChatGPT, Gemini, Perplexity, Claude, and Google AI Overviews — name you, cite you, and recommend you when someone asks a real estate question in your market.

You will run it the same way each time, so you can compare this month to last month and see whether your visibility is improving. The first setup takes about 30 to 60 minutes. After that, a monthly re-run is much faster.

There is no coding and no API keys. You or your AI assistant produce one small data file, and the dashboard reads it.

Before you start

Read the main guide first if you have not. It explains what AEO is, why it matters, and the eight principles behind it.

What you need

Three things, and one of them does almost all the work.

An AI assistant

The WFP enterprise Gemini account in the browser is the recommended path. It is the simplest to set up and the easiest to re-run each month. Any capable assistant works, including Claude Code or OpenCode if you already use them — the setup doc is written for all of them.

The dashboard template

Download dashboard.zip from the repository's latest release. It contains the dashboard page, the sample data, and everything it needs to run offline.

The setup doc

The file AGENT-AEO-SETUP.md is the instruction set you hand to your assistant. It tells the assistant what to ask you, which queries to run, how to score them, and how to produce your data.js. You can give the assistant the raw link below or paste in the file's contents.

https://raw.githubusercontent.com/nigelianarmbuster-cmd/wfp-aeo-guide/main/AGENT-AEO-SETUP.md
You edit one small file

The only file that changes between runs is data.js. Everything else stays as downloaded.

Set it up in six steps

Download the dashboard

Download the template and unzip it somewhere you can find it, such as a folder called AEO in your documents.

Download the dashboard

You can also browse the project source at github.com/nigelianarmbuster-cmd/wfp-aeo-guide.

Hand the setup doc to your AI assistant

Open your assistant and give it the setup doc — either the raw URL or the pasted contents of the file. Then send one line:

Read this setup doc and follow it to build my AEO dashboard.

If your assistant cannot open links, paste the contents of AGENT-AEO-SETUP.md into the chat instead. If it can read attached files, attach the file.

Answer the intake questions

The assistant will ask a short set of questions, one at a time. Have the answers ready:

  1. Your full name, exactly as it should appear in an answer.
  2. Your company or brokerage (usually Washington Fine Properties).
  3. Whether you have your own website, and its address if so.
  4. Where your testimonials and reviews live (Google Business Profile, Zillow, Realtor.com, your own site, or another place).
  5. Your service areas and neighborhoods — the places you want to be known for.
  6. Your main competitors, two to five of them, ideally other agents or teams in the same neighborhoods.
  7. Which answer engines you can access from that list of five.

Run the queries

The assistant runs a fixed set of ten questions — or hands them to you to run and paste back, depending on what it can do. The questions cover how an agent is described, ranked, and compared in your market.

The set always includes a manual check of Google AI Overviews. AI Overviews do not appear for every query, so any that are not shown are recorded as "not shown."

The honesty rule

Answers must be quoted verbatim. If the assistant cannot check an engine, that engine is marked "not evaluated" and its fields are left blank. Nothing is invented, and nothing is guessed. An engine that cannot be checked is simply left out.

Save data.js and open the dashboard

Save the generated data.js file next to index.html in the folder you unzipped, overwriting the sample file inside. Then open index.html in your browser.

If the dashboard still shows a SAMPLE banner at the top, the sample data was not replaced. Check that you overwrote the correct file, and make sure it is named exactly data.js.

Choose your setup

Step 6 is making the run repeatable. Pick the assistant you actually use. The setup doc is the same for all of them — only the way you save and re-run the prompt changes.

Gemini in the browser Recommended

Save the run prompt as a Gem (or as a reusable prompt you can paste) so you do not retype it each month.

  1. Create a Gem in the WFP enterprise Gemini workspace and paste in the recurring run prompt from the setup doc.
  2. Keep your aeo-state.md and your latest data.js in one folder. Re-attach both each run so the assistant remembers your query set and history.
  3. When the run finishes, use Canvas to download the updated data.js.
  4. Save it next to index.html, overwriting the old copy, and reopen the dashboard.

If your enterprise settings limit URL access or Canvas, paste the setup doc text directly and copy the generated file out manually.

Claude Code

Create a custom command file at .claude/commands/wfp-aeo-run.md in your project folder and paste in the recurring run prompt. You then type /wfp-aeo-run each month to re-run it.

Note: Claude Code is moving custom commands into skills, so this path may change. The commands path still works today.

OpenCode

Create a command file at .opencode/commands/wfp-aeo-run.md in your project folder and paste in the recurring run prompt. The singular folder form, .opencode/command/, also works.

Any other assistant

Use this portable prompt. Paste it at the start of each run, along with your current aeo-state.md if you have one.

Read this setup doc and follow it to build my AEO dashboard.
Then run the monthly follow-up: re-run the fixed query set,
score the results, and produce an updated data.js.
Keep answers verbatim, mark anything you cannot check as
"not evaluated", and do not invent results.

Any assistant that can browse the web and produce a file will do the whole run for you. If it cannot browse, it will give you the queries to run by hand.

Mac and Windows

The main path is identical on both. The only differences are the folder locations used by the advanced command-line setups.

Project folders use the same relative path on both systems, so .claude/commands/ and .opencode/commands/ are written the same way wherever your project lives.

Global configuration folders differ only by how each system names the home folder:

Configuration folder locations by operating system.
Tool macOS Windows
Claude Code ~/.claude %USERPROFILE%\.claude
OpenCode ~/.config/opencode C:\Users\<you>\.config\opencode
Gemini ~/.gemini %USERPROFILE%\.gemini

When you save any of these files, save them as UTF-8. For data.js, keep the content ASCII-only — straight quotes and plain hyphens, not curly quotes or typographic dashes. That prevents the dashboard from failing to load.

Troubleshooting

The assistant says it cannot browse the web

It will switch to the chat mode and hand you the queries to run yourself. Run them one at a time, paste each answer back, and it will score them and produce your data.js. Nothing is lost — both modes produce the same file.

An engine blocks automated checks

Some engines limit automated access. Mark that engine "not evaluated" for the affected queries rather than guessing. Do not scrape a site that blocks automated access.

Enterprise Gemini limits URL access or Canvas

Paste the setup doc text directly instead of sharing a link, and copy the generated data.js out of the chat by hand. Your workspace administrator may also need to enable these features.

The SAMPLE banner is still showing

Your new data.js was not saved in the right place or with the right name. It must sit next to index.html and be named exactly data.js. Reload the page after saving.

The dashboard will not load

Open the browser's developer console and look for an error mentioning data.js. A common cause is a curly quote or a typographic dash that crept into the file. Re-save it as ASCII-only, then reload.

Frequently asked questions

How often should I run this?

Monthly is recommended. Answer engines change often, and ten queries are a smoke test rather than a measurement. Track the trend across several months instead of over-reading a single run.

What should I do with the results?

Use them to find the questions where you are missing from the answer, and which sources are cited instead. Then work on the principles in the main guide — being crawlable, answering directly, keeping your facts consistent, and earning mentions and reviews from other sources. The setup doc also produces a prioritized action plan based on your own material.

Can I share my dashboard?

It is built for your own use. The file contains your name and market information, so treat it as internal. The repository's sample dashboard uses fictional data and is the right thing to share as a demonstration.

Does this guarantee I will be recommended?

No. No tool and no document can guarantee a specific answer from an answer engine. This gives you a consistent, honest way to see how you currently appear and to track whether your work is moving the needle.
